# JASKIRAT TEXTILES API - POSTMAN TEST COLLECTION

This document provides sample requests for testing the Jaskirat Textiles API in Postman.

## ENVIRONMENT SETUP

1. Create a new Postman environment with the following variables:
- `base_url`: http://localhost:8000
- `token`: (leave empty initially)
- `admin_token`: (leave empty initially)
- `accountant_token`: (leave empty initially)
- `executive_token`: (leave empty initially)
- `company_code`: (leave empty initially)
- `bill_id`: (leave empty initially)
- `payment_id`: (leave empty initially)

## AUTHENTICATION TESTS

### 1. Executive Login
**Method**: POST
**URL**: {{base_url}}/api/auth/login
**Body**: raw (JSON)
```json
{
    "phone": "9876543212",
    "password": "executive123"
}
```

**Response Handling (Tests Tab)**:
```javascript
if (pm.response.code === 200) {
    var jsonData = pm.response.json();
    pm.environment.set("token", jsonData.access_token);
    pm.environment.set("executive_token", jsonData.access_token);
    pm.test("Executive login successful", function () {
        pm.expect(jsonData.user.role).to.equal("executive");
    });
}
```

## TESTING NOTES

1. **Authentication Flow**:
   - Use the login endpoint to get tokens for different user roles
   - Store tokens in environment variables
   - Use appropriate token for each request based on required permissions

2. **Company & Bill Access**:
   - Executives can only see companies assigned to them
   - All roles can view bills, but with different permissions

3. **Payment Approval Workflow**:
   - Executive creates payment → Status: PENDING
   - Accountant approves → accountant_approved: true
   - Admin approves → admin_approved: true, Status: COMPLETED
   - Bill status updated to PAID or PARTIALLY_PAID

4. **Error Testing**:
   - Try accessing unauthorized resources
   - Try payment approval without proper role
   - Try admin approval before accountant approval

5. **Common Issues**:
   - Make sure all tokens are valid and not expired
   - Check that bill_ids is an array, even for single bill
   - Ensure company_code in payment matches bill's company
   - Payment amount should be valid (greater than 0)

## TYPICAL WORKFLOW EXAMPLE

1. Login as Executive → Get token
2. Get assigned companies → Select company_code
3. Get bills for selected company → Select bill_id
4. Create payment for selected bill
5. Login as Accountant → Get token
6. Get pending payments → Approve payment
7. Login as Admin → Get token
8. Get pending admin approvals → Give final approval
9. Verify bill status is updated to PAID
10. Verify company information is updated (promise_date, credit_date)
